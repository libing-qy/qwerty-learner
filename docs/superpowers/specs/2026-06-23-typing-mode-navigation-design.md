# Typing 页面单词/句子练习导航设计

## 1. 背景

当前 `Typing` 页面已经支持两种练习阶段：

- 单词练习（`trainingMode = 'word'`）
- 连词成句练习（`trainingMode = 'sentence-order'`）

但模式切换仍然主要依赖流程推进：先完成单词，再自动进入句子。左侧列表也只显示单词，无法在句子练习阶段作为句子导航使用。

本次需求是补齐“主动切换”和“列表跳转”能力：

1. 在练习页增加快捷按钮，可直接切换到单词练习或句子练习。
2. 复用现有左侧列表，不新增第二套侧边栏。
3. 左侧列表在句子模式下要显示句子内容，并在点击后跳到对应句子。
4. 句子项显示中英文两部分，并对超出部分进行隐藏。

## 2. 目标与非目标

### 2.1 目标

- 用户在单词模式下可直接切到句子模式。
- 用户在句子模式下可直接切回单词模式。
- 左侧列表根据当前模式展示对应导航内容。
- 点击左侧项后，主练习区跳到对应内容。
- 没有句子资源的词库保持兼容，句子入口禁用且显示 `0 句` 的现有展示不受影响。

### 2.2 非目标

- 不新增独立“句子专用侧边栏”。
- 不修改章节完成语义，仍然保持“词和句都完成才算章节完成”。
- 不改 review mode 的现有语义；review mode 仍只围绕单词练习。
- 不引入新的路由页面或新的全局 store。

## 3. 方案选择

### 方案 A：单一左侧列表按当前模式切换内容（推荐）

- 顶部增加 `单词练习` / `句子练习` 按钮。
- 左侧列表在单词模式渲染单词项，在句子模式渲染句子项。
- 点击列表项跳到当前模式对应的练习对象。

优点：

- 与现有结构最贴近。
- 复用已有 `WordList` 抽屉和打开方式。
- 用户心智简单：当前在练什么，左侧就显示什么。

缺点：

- 左侧列表需要承担两种展示类型。

### 方案 B：左侧列表中混排单词和句子

优点：

- 所有内容一次可见。

缺点：

- 列表很长。
- 激活项和跳转目标不直观。
- 与现有单词练习流程耦合更重。

### 方案 C：在左侧列表内部再加 Tab

优点：

- 信息架构清晰。

缺点：

- 与页面顶部切换按钮重复。
- UI 更重，超出本次最小改动目标。

**结论：采用方案 A。**

## 4. 交互设计

### 4.1 顶部快捷按钮

在 `Typing` 页面头部增加两个按钮：

- `单词练习`
- `句子练习`

行为：

- 当前为单词模式时，`单词练习` 置为高亮态。
- 当前为句子模式时，`句子练习` 置为高亮态。
- 若当前词库没有句子资源，`句子练习` 按钮禁用。
- review mode 下不显示句子切换入口，只保留单词练习相关行为。

### 4.2 左侧列表内容

复用当前 `WordList` 抽屉：

- 单词模式：显示单词列表（保持现状）
- 句子模式：显示句子列表

句子项展示：

- 第一行：中文释义（主信息）
- 第二行：英文句子预览（辅助信息）
- 超长文本使用截断或最大行数限制，避免撑高列表

### 4.3 列表点击行为

- 单词模式下点击单词项：跳到对应单词
- 句子模式下点击句子项：跳到对应句子，并重置当前句子的 token 输入位置

点击列表项后：

- 关闭抽屉
- 主练习区切换到目标项
- 保持当前模式不变

## 5. 状态设计

### 5.1 新增 reducer action

在 `TypingStateActionType` 中补充两类导航 action：

1. 模式切换

   - `SWITCH_TO_WORD_MODE`
   - 保留已有 `SWITCH_TO_SENTENCE_MODE`

2. 句子列表跳转
   - `SKIP_2_SENTENCE_INDEX`

### 5.2 模式切换行为

#### `SWITCH_TO_WORD_MODE`

- `trainingMode = 'word'`
- `isShowSkip = false`
- 不重置 `chapterData.index`
- 不清空单词练习进度
- 保持 `isTyping` 为可继续练习状态

#### `SWITCH_TO_SENTENCE_MODE`

现有逻辑需要补强为两种来源共用：

- 自动从单词阶段切入
- 用户点击顶部快捷按钮主动切入

切入规则：

- 若没有句子资源，不切换
- 若已有句子资源：
  - `trainingMode = 'sentence-order'`
  - 若当前句子索引越界，回到 `0`
  - 重置 `tokenIndex` 和 `inputToken`
  - 保持现有句子累计完成进度，不额外清零

### 5.3 句子跳转行为

`SKIP_2_SENTENCE_INDEX`：

- 更新 `sentenceData.index`
- 重置 `sentenceData.tokenIndex = 0`
- 重置 `sentenceData.inputToken = ''`
- `isShowSkip = false`
- 不修改 `sentenceCount`
- 不修改历史 `userInputLogs`

## 6. 组件设计

### 6.1 `Typing/index.tsx`

职责扩展：

- 在头部增加模式快捷按钮
- 根据 `state.trainingMode` 和 `sentences.length` 控制按钮可用状态与样式
- 按钮点击时 dispatch 对应切换 action

### 6.2 `WordList/index.tsx`

从“单词列表抽屉”升级为“当前练习模式导航抽屉”：

- 读取 `state.trainingMode`
- 单词模式渲染 `WordCard`
- 句子模式渲染新组件 `SentenceCard`
- 点击项后 dispatch 对应索引跳转 action

### 6.3 新增 `SentenceCard`

建议新增文件，例如：

- `src/pages/Typing/components/WordList/SentenceCard.tsx`

职责：

- 展示中文释义
- 展示英文句子预览
- 展示激活态
- 不承担输入逻辑，仅负责导航展示

### 6.4 `WordPanel/index.tsx`

保留其主区域切换逻辑，但不再是唯一模式切换入口：

- 自动切入句子模式的逻辑仍保留
- 顶部按钮和列表跳转成为额外入口

## 7. 边界与兼容性

### 7.1 无句子资源词库

- `句子练习` 按钮禁用
- 左侧列表始终显示单词
- 现有单词流程不受影响

### 7.2 review mode

- review mode 下不开放句子切换
- 左侧列表仍显示单词
- 现有错题复习索引更新逻辑保持不变

### 7.3 已完成章节状态

- 结果页出现后，本次新增导航不生效
- 不允许通过新增按钮绕过结果页状态

## 8. 测试设计

### 8.1 reducer 测试

新增覆盖：

- `SWITCH_TO_WORD_MODE` 能从句子模式切回单词模式
- `SKIP_2_SENTENCE_INDEX` 能跳到指定句子并重置 token 状态
- `SWITCH_TO_SENTENCE_MODE` 在主动切换时不错误清空已加载句子数据

### 8.2 组件测试

新增覆盖：

- 顶部按钮在不同模式下高亮正确
- 无句子资源时，`句子练习` 按钮禁用
- 左侧列表在单词模式下显示单词项
- 左侧列表在句子模式下显示句子项
- 点击句子项后 dispatch 正确的句子跳转 action

### 8.3 回归验证

重点回归：

- 单词练习正常推进
- 单词完成后仍可自动进入句子练习
- 句子练习中切回单词，再切回句子，不会破坏进度和输入状态
- review mode 不出现句子入口

## 9. 实施建议

建议按以下顺序实现：

1. reducer 增加模式切换和句子索引跳转 action，并先补测试
2. 头部增加单词/句子快捷按钮
3. 左侧列表抽象为“按模式渲染不同导航项”
4. 新增 `SentenceCard` 并接入句子跳转
5. 做 focused tests、lint、build 回归

## 10. 验收标准

满足以下条件即视为完成：

1. 练习页顶部可在单词/句子之间直接切换
2. 没有句子资源时句子入口禁用
3. 左侧列表在句子模式下能显示中英文句子导航项
4. 点击左侧句子项后，可直接跳到对应句子练习
5. 点击左侧单词项后，可直接跳到对应单词练习
6. 不破坏现有自动切句子流程、review mode 和章节完成逻辑
